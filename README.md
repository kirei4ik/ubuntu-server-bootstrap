# Ubuntu Server Bootstrap

Интерактивный bootstrap для Ubuntu Server 22.04+.

Основной сценарий — запустить `bootstrap.sh`, ввести адрес сервера, root-пароль, пользователей и порты. Постоянный inventory для первичной настройки не нужен: скрипт создаёт временный inventory и удаляет его после завершения.

Если выполнение прервалось или завершилось ошибкой, при следующем запуске скрипт предложит продолжить с уже введёнными данными либо начать с нуля. Скрипт также сохраняет завершённые этапы: например, после успешной подготовки сервера он продолжит с проверки входа под основным администратором, не повторяя подготовку. После успешного завершения сохранённые временные данные удаляются.

При временном разрыве SSH bootstrap автоматически повторяет Ansible-попытку до трёх раз с паузой 10 секунд. Отдельные SSH-проверки также используют несколько попыток подключения.

## Быстрый запуск

```bash
brew install ansible
chmod +x bootstrap.sh
./bootstrap.sh
```

Мастер запросит адрес сервера и root-пароль, hostname, имя основного администратора (`bestadmin` по умолчанию), публичные SSH-ключи пользователей и дополнительные входящие порты.

Публичный ключ можно скопировать из Bitwarden и вставить прямо в терминал. Приватный ключ должен быть доступен локальному SSH-клиенту через `ssh-agent` или стандартный путь `~/.ssh/id_*`, чтобы скрипт мог проверить вход под новым администратором.

Перед подключением bootstrap получает host key сервера, показывает SHA256 fingerprint и просит подтвердить его. Сверьте fingerprint с панелью VPS-провайдера или консолью сервера. Подтверждённый ключ используется только во временном `known_hosts` и удаляется после завершения.

## Что происходит

Перед изменениями скрипт показывает итоговую конфигурацию: пользователей, SSH-политику, список портов UFW, системные параметры и устанавливаемые пакеты.

Затем выполняются две технические фазы:

1. Под root создаются пользователи, устанавливаются базовые пакеты и системные настройки. Root-доступ сохраняется.
2. Скрипт проверяет вход под основным администратором по ключу. Только после успешной проверки применяются SSH hardening, UFW и security-сервисы.

В результате настроены:

- пользователи и SSH-ключи;
- hostname;
- SSH только по ключам, root SSH отключён;
- `PubkeyAuthentication yes` и `KbdInteractiveAuthentication no`;
- UFW с обязательным SSH-портом и добавленными пользователем правилами;
- fail2ban, auditd и AppArmor;
- timezone, locale и chrony;
- logrotate/journald, sysctl и swap;
- базовые обновления и необходимые системные пакеты.

Дополнительные порты добавляются к обязательному `22/tcp`, а не заменяют его. По умолчанию открывается только SSH.

## Пользователи

Основной администратор всегда получает `sudo`. Для дополнительных пользователей доступны роли:

- `admin` — sudo-доступ без пароля;
- `user` — обычная учётная запись без sudo.

Ключи передаются через временный файл с правами `0600`, после завершения файл удаляется. Ключи и root-пароль не записываются в репозиторий.

## Опциональные возможности

Monitoring и backup намеренно не входят в bootstrap.

### Monitoring

`playbook_monitoring.yaml` устанавливает node_exporter, health-check и дополнительные локальные инструменты. Для полезного мониторинга нужен внешний Prometheus/Grafana или другой сборщик метрик, а также отдельная настройка уведомлений. Без этого сервер лишь отдаёт метрики локально.

### Backup

`playbook_backup.yaml` настраивает Restic, systemd timers и проверку восстановления. По умолчанию репозиторий локальный (`/backup/repository`), поэтому это не защита от потери самого сервера.

Перед включением backup нужно настроить удалённое хранилище, пароль Restic и уведомления. Backup нельзя считать готовым, пока не проверено реальное восстановление файлов.

## Постоянное управление серверами

Bootstrap не сохраняет inventory. Если сервер нужно обслуживать этим проектом дальше, создайте локальный файл вне репозитория:

```yaml
all:
  hosts:
    server-01:
      ansible_host: 203.0.113.10
      ansible_user: bestadmin
      ansible_private_key_file: ~/.ssh/id_ed25519
      ansible_port: 22
```

Запуск дополнительных playbook’ов:

```bash
ansible-playbook -i maintenance-inventory.yml playbook_monitoring.yaml
ansible-playbook -i maintenance-inventory.yml playbook_backup.yaml --ask-vault-pass
```

## Важные меры предосторожности

- До запуска убедитесь, что есть консоль провайдера или другой аварийный доступ.
- Если проверка входа под администратором не прошла, hardening не запускается.
- Перед включением дополнительных портов проверьте, что они нужны сервису.
- Не храните root-пароли и приватные ключи в проекте.

## Структура

```text
bootstrap.sh                       # основной пользовательский сценарий
playbook_bootstrap_prepare.yaml    # пользователи, пакеты, system и подготовка
playbook_bootstrap_harden.yaml     # SSH hardening, UFW и security-сервисы
playbook_monitoring.yaml           # опционально
playbook_backup.yaml               # опционально
roles/                             # реализации Ansible-модулей
group_vars/all/vars.yml             # базовые значения конфигурации
```
